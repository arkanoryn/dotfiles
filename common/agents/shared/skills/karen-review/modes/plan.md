# Mode: plan

Input: an execution folder (`pipeline.conf`, `common-understanding.md`, `agent-*.md`) generated by `to-issues`, plus the PRD it came from. Read all of them. **Read-only — fix nothing.**

## Pipeline integrity

- Syntax errors (`bash -n pipeline.conf`; run `bash scripts/delegate_agents.sh --validate <folder>` if the runner exists).
- `PIPELINE` ids without an `agent-<id>.md`, task files not in the pipeline, deps referencing missing ids, cycles.
- Invalid providers, missing `provider_<name>()` functions, missing `SLOTS` entries.
- Gate shape: every seam ends `karen-<seam>` → `fix-<seam>` → `commit-<seam>`; the pipeline ends `karen-final` → `fix-final` → `commit-final`; downstream seams depend on `commit-<seam>`, never on raw tasks or the bare fix.

## Commit safety

- Every `commit-*` task's provider pool has exactly 1 slot (serialized commits).
- Commit tasks stage ONLY their seam's owned files by explicit path — flag any `git add -A`, `git add .`, or `git add -u`, and any missing "check `git diff --cached` is empty first" guard.
- `scripts/format.sh` runs inside commit tasks only — flag it as a free-floating or parallel task (it would rewrite files other seams still own).
- `commit-*` tasks are the ONLY tasks allowed git write commands; implementation and fix tasks must forbid commit/stage/push.

## Resolver

- `RESOLVER_PROVIDER` is set and names a defined provider function; `RESOLVER_MAX` / `RESOLVER_TIMEOUT_SEC` are sane for the pipeline's task sizes.
- The plan does not lean on the resolver to paper over vague tasks — the resolver repairs broken runs, not broken breakdowns.

## Task quality

- Granularity: flag any task exceeding the to-issues hard limits — one observable behavior, ≤ 3 files edited, ≤ 5 acceptance criteria, ~15 minutes for a thinking-off agent.
- Tasks that need unstated context from the parent chat (fresh sessions know nothing).
- Architecture, API, security, data-model, or scope decisions smuggled into task files instead of the PRD/ADRs.
- Ambiguous acceptance criteria that would make a low-thinking agent guess; criteria not provable by a command or test named in the same file.
- Missing or unprovable validation commands; missing TDD instructions in implementation tasks.
- Thinking levels: `off` by default, `high` only for `karen-*`/`fix-*`, `medium` for `commit-*` and genuinely tricky tasks — flag blanket raises.

## Parallelism

- Overlapping file ownership between tasks that can run concurrently (same wave or independent seams).
- Under-parallelization: independent work needlessly serialized when provider slots are free.
- Over-parallelization: concurrent tasks racing on shared files, configs, or generated code.

Verdict values: `BLOCKED` | `NEEDS FIXES` | `NO MEDIUM+ ISSUES FOUND`.
